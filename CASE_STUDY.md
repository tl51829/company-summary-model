# Company Summaries

## What I built

I built a system that generates summaries for the 50 companies for different system prompts. Each system prompt is a summary version. Every prompt uses a different prompting technique. To test how each prompt/version did, I also built a system that determines the BERTScore metric of each version. The hybrid/combined system prompt did the best while using no system prompt (baseline) did the worst.

Running src/generate.py will generate 6 versions of summaries for the 50 companies. The 6 versions use different system prompts stored in src/prompts.py.

Running src/validate.py will determine the BERTScore metric for a sample of 10 companies stored in test/test_companies.jsonl. This will be done for all 6 versions (system prompts). The results after determining the BERTScore will be stored in test/result/. The output summaries will be stored in test/output/

## How I determine what a good summary is for this team, and why

I used the BERTScore metric. It measures how semantically similar 2 text are. I generated summaries for the sample of 10 companies using ChatGPT (I didn't have enough time to write them by hand). These summaries act as reference and are stored in test/expected/test_expected.jsonl. The summaries generated by the LLM are compared to these reference. 

I used BERTScore, because it is a widely used metric to determine whether a summary generated by AI is good. If an LLM generated a semantically similar summary to a summary writte by a human professional (in this case, it was generated by a better model), we can say that the LLM did a good job generating the summary.

## What I'd do next, and how I'd keep improving it

1. Use actual benchmarks instead of just determining metric value, e.g. FinanceBench, The Financial Narrative Summarisation Shared Task (FNS 2020), etc. The reason why I didn't do this is because these benchmarks use PDFs or text files as input as oppose to JSON (which is what we are dealing with in this case). So, some kind of extraction or NLP would need to be done, which requires time.
2. Fine-tune model to specialize in generating summaries for this case. The reason why I didn't do this is because I don't have sufficient data to fine-tune the model.

## Additional Information

### LLM Used

I used the LLAMA 3.2 Instruct (3B) model. There are 2 ways I used this model. The first way is by using HuggingFace Inference Provider. To use this, you have to set your access token as an environment variable. The second way is locally hosting it using Ollama. I used Ollama for testing my code, and HuggingFace for the rest. To use Ollama, you have to download the cas/llama-3.2-3b-instruct model and set USE_OLLAMA constant in src/summarize.py to True.

# Files Added

## Source Code

src/prompt.py -- contains list of system prompts (1 version per prompt)
src/load_data.py -- contains function that when given path of jsonl file, returns a list of company as objects
src/summarize.py -- contains function that when given list of companies, output path, and system prompt, returns a dictionary of the generated summaries and write the generated summaries in output path
src/generate.py -- when run, for each prompt in prompt.py, write the summaries generated in summaries/
src/validate.py -- when run, for each prompt in prompt.py, generate summary for the sample of 10 companies and determine BERTScore when compared to reference summary

## Testing/Measuring

test/ -- folder with testing data
test/test-companies.jsonl -- sample of 10 companies from data/companies.jsonl (picked by ChatGPT to be very different from each other)
test/expected/test_expected.jsonl -- reference summary of the 10 companies (generated by ChatGPT)
test/output/ -- folder with summary output of the 10 companies (1 file per version)
test/result/ -- folder with metric measurement result of summary output of the 10 companies (1 file per version)
